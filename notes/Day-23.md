# Day 23

## What did I build?

Today I built a semantic search system using custom embeddings generated by NVIDIA's `nemotron-3-embed-1b` model. Instead of relying on ChromaDB's default embedding model, I generated embeddings for my CommerceOps policy documents, stored them together with the documents, and queried the vector database using embedded user questions.

## What did I learn?

I learned that production Retrieval-Augmented Generation (RAG) systems usually separate embedding generation from vector storage. I also learned how to generate embeddings myself, store them in ChromaDB, and retrieve documents by supplying query embeddings instead of raw text.

## Biggest challenge today

The biggest challenge was understanding why some semantically related questions did not retrieve the document I expected. Initially, refund-related questions returned the shipping policy instead of the refund policy.

## How did I solve it?

I experimented with the wording of my stored documents. By changing the refund policy to include terms such as "return", "products", "purchase", and "refund", the retrieval quality improved significantly. I also improved the email policy wording so it better matched natural user questions.

## What surprised me?

I was surprised by how much the wording of a document affects retrieval quality. Simply rewriting the document with richer and more descriptive language noticeably improved the semantic search results without changing any retrieval code.

## One thing I still don't understand

I'm curious to learn how production AI teams evaluate different embedding models and systematically measure retrieval accuracy before choosing one for a RAG application.

## Summary

Today I gained full control over the embedding pipeline by generating my own embeddings with NVIDIA's embedding model and storing them inside ChromaDB. I also discovered that high-quality document writing is just as important as choosing a good embedding model, because better document wording leads to more accurate semantic retrieval.
